# PDF変換ツール 設計書

- 作成日：2026-10-05
- 状態：レビュー待ち

「（提案）」と付いた項目は、会話では決めておらず設計時に補った細部。

## 1. 目的と前提

### 目的
スマホとPCのブラウザから使える、PDFの作成・編集ツールを作る。

### 決まったこと
- 機能：画像→PDF、PDFの結合、分割、回転、圧縮、ページのプレビュー
- スマホでも使える。GitHub Pages で公開し、外出先からも使える
- 変換はすべてブラウザ内で行い、ファイルはどこにもアップロードしない
- 作り方：HTML/CSS/JavaScript だけで作り、ビルド（公開用ファイルへの変換）は行わない

### 対象外（今回は作らない）
- Word / Excel / PowerPoint → PDF（GitHub Pages では Office を動かせないため。当面は Office の「名前を付けて保存 → PDF」で代用）
- パスワード付きPDFの解除
- PWA（ホーム画面へのアプリ追加・オフライン動作）。後から追加は可能
- 1つのPDF内でのページの並べ替え・削除

### 想定する利用者と環境
- 主な利用者は作成者本人（公開URLなので誰でも開けるが、処理は各自の端末内で完結）
- 対象ブラウザ：最新版の Chrome / Edge（PC）、Safari（iPhone）、Chrome（Android）

### 完成の目安
- スマホで写真を選んでPDFにし、端末に保存できる
- PDFの結合・分割・回転・圧縮をスマホとPCの両方で行い、保存できる
- 自動テストがすべて通り、手動確認リスト（9章）をスマホとPCで満たす

## 2. 全体構成

### 画面
1つのHTMLページの中で画面を切り替える。

- **ホーム画面**：5つの大きなボタン（画像→PDF／結合／分割／回転／圧縮）
- **各機能の画面**：左上に［← 戻る］。スマホの縦長画面を基準にし、PCでも同じ画面を使う

### 役割の分け方
- **画面担当**（`main.js`）：ボタン操作、一覧表示、エラー文の表示。処理部品を呼び出す
- **処理担当**（`merge.js` など）：PDFのデータ（バイト列）を受け取り、新しいデータを返すだけ。画面やボタンを一切知らない
- **ブラウザ専用担当**（`preview.js`、`image-decode.js`、`download.js`）：画像の描画やダウンロードなど、ブラウザの機能が必要な処理

処理担当はブラウザでも Node.js でも動くように書き、自動テストの対象にする。

### ファイル構成

```
index.html              画面の骨組み
css/style.css           見た目（スマホ基準）
js/
  main.js               画面担当
  errors.js             エラーの種類（エラーコード）の定義
  pdf-load.js           PDFの読み込み・ページ数取得・読み込みエラーの判定
  page-range.js         ページ指定（例：1-3, 5）の読み取りと文字列化
  image-to-pdf.js       画像→PDF（配置計算とPDF組み立て）
  image-decode.js       画像の読み込み・向きの補正・形式変換（ブラウザ専用）
  merge.js              結合
  split.js              分割
  rotate.js             回転
  compress.js           圧縮
  preview.js            ページを画像として描く（pdf.js を使用、ブラウザ専用）
  download.js           保存・ZIP作成（ブラウザ専用）
lib/
  pdf-lib.esm.min.js    PDFの作成・編集
  pdf.min.js            pdf.js（PDFの描画）
  pdf.worker.min.js     pdf.js の裏側処理（Worker）
  jszip.min.js          ZIP作成
  LICENSES/             各部品のライセンス文
tests/                  自動テスト
package.json            テスト実行用の設定（公開には無関係）
docs/                   設計書など
```

### 外部部品
| 部品 | 用途 | ライセンス |
|---|---|---|
| pdf-lib | PDFの作成・結合・分割・回転 | MIT |
| pdf.js（pdfjs-dist） | プレビュー、強い圧縮のためのページ描画 | Apache-2.0 |
| JSZip | 分割結果のZIP化 | MIT（MIT/GPLv3 のデュアル） |

- インターネットから毎回読み込まず、`lib/` に同梱する。版は実装時点の最新安定版に固定する
- ライセンス文を `lib/LICENSES/` に置く
- （提案）pdf.js の配布ファイルは拡張子 `.mjs` だが、配信サーバーによって正しく扱われない場合があるため、同梱時に `.js` にそろえる
- JavaScript は ES モジュール（`import` で部品を読み込む形式）で書く。pdf-lib は ES モジュール版を使い、ブラウザとテストで同じファイルを読む

## 3. 機能の詳細

### 3.1 画像→PDF
1. ［画像を選ぶ］で画像を選ぶ（複数可・追加可）。スマホでは写真ライブラリ／カメラから選べる
2. サムネイル一覧を表示。［↑］［↓］で並べ替え、［×］で削除
3. ページサイズを選ぶ：「A4」（初期値）／「画像と同じ大きさ」
4. ［PDFを作成］→ `images.pdf` を保存

**画像の取り込み**
- すべての画像を一度ブラウザ上で描き直す。これにより、スマホ写真の向き情報（EXIF）を反映して正しい向きにし、JPEG/PNG 以外の形式（WebP など）にも対応する
- PNG は PNG のまま（透明部分を保つ）、それ以外は JPEG（品質 0.92）として PDF に入れる（提案）
- 画像の画素数は減らさない（ファイルを軽くしたい場合は圧縮機能を使う）。下の「縮小」はページ上での表示の大きさの話

**ページへの配置**（提案）
- 画像の大きさは 1 ピクセル = 0.75 pt として扱う（pt は PDF の長さの単位。1 pt = 1/72 インチ）
- 「A4」：画像が横長（幅 > 高さ）ならA4横向き、それ以外はA4縦向き。四辺に 10mm の余白を取り、その内側に縦横比を保って収める。**縮小のみ行い、拡大はしない**。中央に配置する
- 「画像と同じ大きさ」：ページの大きさ＝画像の大きさ（余白なし）

### 3.2 結合
1. ［PDFを選ぶ］で複数選ぶ（追加可）
2. 一覧に「1ページ目のプレビュー・ファイル名・ページ数」を表示。［↑］［↓］［×］で調整
3. ［結合する］→ `merged.pdf` を保存（2つ以上選んだときだけ押せる）

### 3.3 分割
1. ［PDFを選ぶ］で1つ選ぶ →「全12ページ」と表示し、全ページのプレビュー一覧を出す
2. 方法を選ぶ

| 方法 | 入力 | 結果 | 保存名 |
|---|---|---|---|
| ページを選んで取り出す | 例 `1-3, 5` | 指定ページを集めた PDF 1つ | `元の名前_抽出.pdf` |
| 1ページずつバラバラに | なし | 全ページを個別のPDFにしてZIP | `元の名前_分割.zip`（中身 `元の名前_p01.pdf` …） |
| 指定ページで区切る | 例 `1-3, 4-10` | 範囲ごとのPDFをZIP | `元の名前_分割.zip`（中身 `元の名前_p1-3.pdf` …） |

- 「取り出す」では、プレビューをタップしてページを選べる。タップすると入力欄に反映され、入力欄を書き換えるとプレビューの選択表示も更新される
- バラバラ時の番号は、全ページ数の桁数に合わせてゼロ埋めする（例：12ページなら `p01`〜`p12`）（提案）

### 3.4 ページ指定の書き方（`page-range.js`）
- ページ番号は 1 から数える
- カンマで区切る。半角 `,`、全角 `，`、読点 `、` のどれでもよい
- 範囲は `開始-終了`。区切り記号は `-`、`－`、`~`、`〜` のどれでもよい（提案）
- `5-` は「5ページから最後まで」（提案）
- 全角数字・空白は許容する（スマホの日本語入力対策）
- エラーになる入力：空、数字以外、0 以下、全ページ数を超える番号、開始 > 終了（例 `5-3`）
- 「取り出す」では、結果を**昇順に並べ、重複を除く**（例 `5, 1-3, 2` → 1,2,3,5）（提案）
- 「区切る」では、カンマで区切った**項目ごとに1ファイル**、入力した順に作る。範囲の重なりは許す
- ページ番号の配列を文字列に戻す関数も用意する（例 [1,2,3,5] → `1-3, 5`）。プレビューのタップ選択を入力欄へ反映するのに使う

### 3.5 回転
1. ［PDFを選ぶ］で1つ選ぶ → 全ページのプレビュー一覧
2. 各ページの［⟳］で時計回りに 90° ずつ回転（プレビューも回転して表示）。［全ページ ⟳］［全ページ ⟲］もある
3. ［保存］→ `元の名前_回転.pdf`
- 元からページに付いている回転に、指定した角度を足す（360° で一周）。画質は変わらない

### 3.6 圧縮
1. ［PDFを選ぶ］で1つ選ぶ
2. 方式を選ぶ
   - **画質そのまま**：PDF内部の構造を整理して保存し直す。見た目は変わらないが、減り方は小さい
   - **強く圧縮**：各ページを画像として描き直し、JPEGで作り直す。［弱・中・強］を選ぶ。画面に「文字のコピー・検索ができなくなります」と注意書きを出す
3. ［圧縮する］→「3.2MB → 0.8MB（75%減）」と、圧縮後の1ページ目のプレビューを表示
4. 画質を確認して［保存］→ `元の名前_圧縮.pdf`

**強く圧縮の設定**（提案）
| 段階 | 解像度 | JPEG品質 |
|---|---|---|
| 弱 | 200 dpi | 0.85 |
| 中（初期値） | 150 dpi | 0.70 |
| 強 | 100 dpi | 0.50 |

- 作り直したページの大きさは元ページの見た目の大きさ（回転を反映済み）と同じにする
- ページを画像にする処理は `compress.js` の外から渡す形にする（ブラウザでは `preview.js` を使い、テストでは偽物の画像を渡す）。これでPDFの組み立て部分を自動テストできる

### 3.7 プレビュー（`preview.js`）
- pdf.js でページを画像として描く。重い処理は Worker（画面とは別の裏側の処理）で行う
- 一覧では、画面に見えたページだけを描く（遅延読み込み）。スマホで多ページのPDFを開いても固まらないようにするため
- サムネイルの幅は画面上で約 150px（提案）

## 4. 処理部品の入出力

ここでの「バイト列」は `Uint8Array`（PDFファイルの中身そのもの）。

| ファイル | 関数 | 入力 → 出力 |
|---|---|---|
| page-range.js | `parsePageRange(text, pageCount)` | 文字列, 全ページ数 → 範囲ごとのページ番号の配列（例 `[[1,2,3],[5]]`） |
| | `toSortedUniquePages(groups)` | 上の結果 → 昇順・重複なしのページ番号配列 |
| | `formatPageRange(pages)` | ページ番号配列 → 文字列（例 `1-3, 5`） |
| image-to-pdf.js | `computePlacement(widthPx, heightPx, mode)` | 画像の大きさ, `"a4"`/`"fit"` → ページの大きさと画像の位置・大きさ（pt） |
| | `imagesToPdf(images, mode)` | `{bytes, type: "jpeg"/"png", widthPx, heightPx}` の配列 → PDF バイト列 |
| merge.js | `mergePdfs(pdfs)` | PDF バイト列の配列 → PDF バイト列 |
| split.js | `extractPages(pdf, pages)` | PDF, ページ番号配列 → PDF |
| | `splitEach(pdf)` | PDF → `{pages, bytes}` の配列 |
| | `splitByRanges(pdf, groups)` | PDF, 範囲ごとの配列 → `{pages, bytes}` の配列 |
| rotate.js | `rotatePages(pdf, rotations)` | PDF, `{ページ番号: 追加角度}` → PDF |
| compress.js | `compressLight(pdf)` | PDF → PDF |
| | `compressStrong(pdf, level, renderPage)` | PDF, `"low"/"medium"/"high"`, ページ描画関数 → PDF |
| pdf-load.js | `loadPdf(pdf)` | PDF バイト列 → pdf-lib の文書。壊れていれば `INVALID_PDF`、パスワード付きなら `PASSWORD_PROTECTED` を出す。他の処理部品はすべてこれを通して読み込む |
| | `getPageCount(pdf)` | PDF バイト列 → ページ数 |

## 5. エラーの扱い

### 方針
- 処理担当は「エラーの種類（コード）」だけを出す（`errors.js` の `PdfToolError`）。画面担当がコードを日本語の文に直して、画面内に表示する
- ブラウザ標準のポップアップ（alert）は使わない
- 失敗しても、選んだファイルや設定は消さない

### エラーコードと表示
| コード | 起きる場面 | 表示（例） |
|---|---|---|
| `UNSUPPORTED_FILE` | PDF欄にPDF以外を選んだ | 「〇〇.jpg はPDFではないため追加しませんでした」（そのファイルだけ除外） |
| `INVALID_PDF` | 壊れた・読めないPDF | 「〇〇.pdf を読み込めませんでした。ファイルが壊れている可能性があります」 |
| `PASSWORD_PROTECTED` | パスワード付きPDF | 「パスワードで保護されたPDFには対応していません」 |
| `UNSUPPORTED_IMAGE` | ブラウザが開けない画像 | 「〇〇 は開けない画像形式です。JPEGやPNGで保存し直してください」 |
| `INVALID_PAGE_RANGE` | ページ指定の誤り | 入力欄の下に赤字で具体的に（例「15ページはありません（全12ページ）」）。直すまで実行ボタンは押せない |
| `TOO_LARGE` | メモリ不足などで処理できない（ブラウザのメモリ関連のエラーを捕まえて変換） | 「ファイルが大きすぎてこの端末では処理できませんでした。ページ数を減らすか、PCでお試しください」 |
| `UNKNOWN` | 想定外 | 「予期しないエラーが発生しました」（詳細はコンソールに記録） |

### その他の表示
- 処理中はボタンを押せなくし、「処理中… 3/12ページ」のように進み具合を出す
- 選んだファイルの合計が 50MB を超えたら、実行前に「大きいファイルのため、スマホでは時間がかかるか失敗する場合があります」と注意を出す（実行は可能）
- 圧縮後のほうが大きい場合は「元のファイルより大きくなりました。保存する必要はありません」と表示する（保存ボタンは残す）

## 6. 自動テスト

- Node.js 標準のテスト機能（`node --test`）を使う。追加のインストールは不要
- テスト用PDFはテストの中で pdf-lib を使って作る（サンプルファイルは置かない）
- パスワード付きPDFのテストには、暗号化の印を付けた最小限のPDFをテスト内で作る

| 対象 | 確かめること |
|---|---|
| page-range | 正しい入力の読み取り（全角・空白・`5-` を含む）、各エラー、昇順・重複除去、文字列化 |
| image-to-pdf | 縦長／横長／小さい画像でのA4配置（向き・余白・縮小のみ・中央）、「画像と同じ大きさ」、ページ数 |
| merge | ページ数の合計と順番 |
| split | 3方式のページ数と中身（各ページの目印で確認） |
| rotate | 指定ページだけ回転、元の回転への加算、360°で一周 |
| compress | 画質そのまま：ページ数が同じで開ける。強く圧縮：偽の描画関数でページ数・ページの大きさが正しい |
| errors | 壊れたPDF → `INVALID_PDF`、パスワード付き → `PASSWORD_PROTECTED` |

## 7. ローカルでの確認

- ES モジュールはHTMLファイルを直接開くだけでは動かないため、PCで確認するときは一時的なローカルサーバー（例：`npx http-server`）で開く
- `package.json` に `test`（自動テスト）と `serve`（ローカルサーバー）のコマンドを用意する

## 8. 公開手順（GitHub Pages）

1. 作業フォルダを Git で管理する
2. GitHub にリポジトリを作る（名前は英数字。例：`pdf-tool`）。無料プランで GitHub Pages を使うため**公開リポジトリ**にする。公開されるのはプログラムだけで、利用者のファイルは公開されない
3. ファイルを GitHub にアップロード（push）する
4. リポジトリの設定で Pages を有効にする（公開元：main ブランチの最上位フォルダ）
5. `https://<ユーザー名>.github.io/pdf-tool/` で開けることを確認し、スマホでブックマークする
